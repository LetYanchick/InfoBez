# SecureTrial — лабораторная работа №1

Linux/C++17 реализация триал-ограничения на 4 запуска.

## Сборка

```bash
cmake -S . -B build
cmake --build build
./build/SecureTrial
```

Администраторские права не требуются.

## Проверка пункта 5

После сборки:

```bash
strings build/SecureTrial | grep -E '\.config|\.local|\.cache|sysdata|appdata|desktop-data|m\.dat|x\.dat|desktop\.dat'
```

Команда должна ничего не вывести.

Пути контрольных файлов находятся в `main.cpp` только в виде XOR-обфусцированных массивов байтов. Они восстанавливаются во время выполнения.

## Проверка количества запусков

Программа должна запуститься 4 раза. На пятом запуске:

```text
Trial period has ended or control data is invalid.
```

## Где хранятся данные

Фактические пути формируются относительно `$HOME`; три файла находятся в разных пользовательских каталогах. Их читаемые названия отсутствуют в строковой таблице исполняемого файла.

## Важное замечание для Linux

Лабораторное задание сформулировано с учетом файловой системы/ОС, где можно программно вернуть дату и время файла. В Linux обычному пользовательскому процессу доступно восстановление `atime` и `mtime`, а время создания файла (birth time) нельзя стандартно установить обратно. Поэтому программа:

- сохраняет размер контрольного файла равным 8 байтам;
- не пересоздает существующие контрольные файлы при обычном обновлении;
- восстанавливает `atime` и `mtime` после записи;
- сохраняет исходный inode и, следовательно, исходное время создания/birth time, пока файл не удаляется.

Это ограничение платформы следует отдельно указать в отчете.

## Проверка размера и времени

Можно посмотреть:

```bash
stat ~/.config/.cache/.sysdata/m.dat
stat ~/.local/share/.appdata/x.dat
```

Эти команды предназначены для проверки результата преподавателем. В исходном коде открытых строк этих путей нет.

## Что реализовано

1. Два независимых файла с настоящим счетчиком.
2. Контрольные файлы находятся вне каталога программы.
3. Счетчик хранится в зашифрованном виде двумя собственными алгоритмами.
4. Работа выполняется без sudo/admin.
5. Пути обфусцированы собственным преобразованием и отсутствуют в открытом виде в бинарнике.
6. Между чтением и анализом есть нейтральные операции.
7. Нет отдельной функции проверки счетчика; проверки расположены непосредственно в `main`.
8. После сравнения сначала выполняется нейтральная ветка, затем следует действие.
9. Результат проверки не сохраняется в `bool` или другой отдельной переменной.
10. Есть отвлекающий контрольный файл.
11. Для двух основных файлов используются разные алгоритмы.
12. Реестра в Linux нет; пункт неприменим, отвлекающий файл используется вместо него.
13. Используются безусловные переходы и нейтральные имена переменных/меток.
